# Transport, Loop, and Render

## Playback

| Control | Key | Behavior |
| --- | --- | --- |
| Play | **Space** | Starts from the play start. Pressing it again stops and returns to the play start. |
| Play / pause button | Top bar | Starts playback, or pauses at the current position. |
| Stop | **Shift+Space** | Stops and returns to the play start. |
| Stop button | Top bar | Same as the Stop shortcut. |
| Loop | Top bar or **Cmd+L** | Enables or disables looping. |
| Metronome | Top bar | Enables the click. |
| Record | Top bar or **Cmd+R** | Starts playback and recording when stopped. If already playing, engages recording without restarting playback. Pressing it again while recording disengages recording but keeps playing. |

The playhead moves during playback. Stop returns to the last play start, which
is the position captured when playback began. Stop also sends all-notes-off and
renders the effect tail with clip playback disabled.

The metronome is generated by the engine and accents the first beat of each
bar. Its on/off state is stored in the project.

## Recording

Recording is linear and audio-only in the current implementation.

1. Optionally name inputs in **Settings > Audio > Inputs & Outputs**. Named
   inputs appear first in the track input picker.
2. Select an audio track and choose an input in the info panel. Mono and stereo
   inputs are supported.
3. Arm zero or more audio tracks with **R** in the track header or info panel.
4. Press **Record** in the top bar or **Cmd+R**. If playback is stopped, it
   starts from the play start and begins recording. If playback is already
   running, it engages recording at the current playhead without restarting
   playback.

While recording, each armed track records from its input. The clip starts at
the playhead where capture began and grows with the playhead, showing its
waveform while recording. Notwig compensates takes using the measured input and
output latency. An armed track's monitoring mode controls whether its input is
monitored through the track chain, monitored directly with low latency, or not
monitored at all.

Pressing Record again finalizes the current clips at the current playhead and
leaves playback running. Pause and Stop also finalize the clips and disengage
recording, so the next playback does not record until Record is pressed again.
With no armed tracks, recording can still be engaged but no clips are created.

Finishing a take:

- writes the captured channels into the project as a stereo float WAV asset;
- replaces existing clips in the recorded range on the armed track;
- inserts a clip named **Recording**;
- selects the new clip;
- is undone as one document edit.

If the project has not been saved yet, the take is staged in a temporary
directory until the project is saved. Notwig compensates new takes using the
measured input and output latency reported by the audio callback timestamps.
Input devices must support the project sample rate. Browser recording uses the
**Web Audio** driver, asks for microphone permission when an armed track first
opens its input, and needs a user gesture to start the audio engine.

## Play start versus playhead

The arranger ruler sets the play start, not a live seek. Clicking the ruler
while playback runs changes where playback returns when you stop; it does not
jump the current playback position. Notwig does not implement scrubbing or
arbitrary seek gestures.

## Loop range

- Shift-drag the ruler to set the loop range.
- Drag the loop rectangle's edges to resize it.
- Use **Cmd+L** with a time selection to loop that range.
- Use **Cmd+L** without a time selection to toggle looping.

Loop wrapping is sample-accurate. Blocks are split at the loop boundary, so
notes and audio events that cross the boundary are scheduled correctly.

## Tempo and time signature

The top bar edits the global tempo and time signature. Both are stored in the
project.

- Tempo is one BPM value for the whole project. Tempo automation and a tempo
  map are not implemented.
- Audio clips are sample-locked. Changing tempo rescales unsliced clip ranges so
  their sample duration stays fixed.
- Time signature is one numerator and denominator for the whole project.
- Time signature changes and markers are not implemented.

## Render mixdown

Open **FILE > Render Mixdown…** to render offline. The dialog sets:

- **File format**: WAV, AIFF, FLAC, MP3, or OGG Vorbis.
- **Bit depth**: 16-bit, 24-bit, or 32-bit where the format supports it.
- **Dither** and **Normalize**.
- **Export stems**, which writes one file per track in addition to the mix.
- **Range**, in beats. **Copy loop range** fills the range from the current loop.

The render runs offline through the same engine path as playback. Latency
compensation, device processing, and the master chain are included.

The default range spans the arrangement. If the end is not after the start, the
**Render…** button is disabled. The output path is chosen after starting the
render.

## Command line rendering

The application binary can render without opening the window:

```sh
cargo run -p notwig-app -- render path/to/project.notwig out.wav
cargo run -p notwig-app -- render path/to/project.notwig out.wav --start 8 --end 32
```

`--start` and `--end` are in beats. The CLI render writes a WAV file.

Other CLI commands:

```sh
cargo run -p notwig-app -- new path/to/project.notwig
cargo run -p notwig-app -- demo
cargo run -p notwig-app -- info path/to/project.notwig
```

Run `notwig --help` for the command list, or `notwig <command> --help` for the
options of a specific command.

### Loopback latency measurement

The native CLI can measure the round trip from the default output to the
selected input by playing periodic clicks and detecting them in the recorded
microphone signal:

```sh
cargo run -p notwig-app -- loopback
cargo run -p notwig-app -- loopback --duration 8 --interval-ms 500 --out loopback.wav
cargo run -p notwig-app -- loopback --driver CoreAudio --device "Aggregate Device" --input-device "Aggregate Device"
```

The report shows every detected click latency, the mean/min/max and spread, the
sample-rate offset, and a linear drift estimate in milliseconds per second. A
stable loopback should have a near-constant latency. A nonzero drift indicates
that input and output are running on different clocks. `--out` keeps the captured
microphone recording for waveform inspection.

## What is not implemented

MIDI recording, loop recording, punch in and out, count-in, take lanes, and
comping are not available. Audio recording captures one mono or stereo input
per track and monitoring is tied to record arm. See the
[Roadmap](../03_development/06_roadmap.md) for the current status.
