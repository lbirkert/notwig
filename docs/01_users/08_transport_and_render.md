# Transport, Loop, and Render

## Playback

| Control | Key | Behavior |
| --- | --- | --- |
| Play | **Space** | Starts from the play start. Pressing it again stops and returns to the play start. |
| Play / pause button | Top bar | Starts playback, or pauses at the current position. |
| Stop | **Shift+Space** | Stops and returns to the play start. |
| Stop button | Top bar | Same as the Stop shortcut. |
| Loop | Top bar or **Cmd+L** | Enables or disables looping. |
| Metronome | Top bar | Enables the click. |

The playhead moves during playback. Stop returns to the loop start when looping
is enabled, otherwise to beat zero or the last play start. Stop also sends
all-notes-off and renders the effect tail with clip playback disabled.

The metronome is generated by the engine and accents the first beat of each
bar. Its on/off state is stored in the project.

## Play start versus playhead

The arranger ruler sets the play start, not a live seek. Clicking the ruler
while playback runs changes where playback returns when you stop; it does not
jump the current playback position. Notwig does not implement scrubbing or
arbitrary seek gestures.

## Loop range

- Shift-drag the ruler to set the loop range.
- Drag the loop rectangle's edges to resize it.
- Use **Cmd+L** with a time selection to loop that range.
- Use **Cmd+L** without a time selection to toggle looping.

Loop wrapping is sample-accurate. Blocks are split at the loop boundary, so
notes and audio events that cross the boundary are scheduled correctly.

## Tempo and time signature

The top bar edits the global tempo and time signature. Both are stored in the
project.

- Tempo is one BPM value for the whole project. Tempo automation and a tempo
  map are not implemented.
- Audio clips are sample-locked. Changing tempo rescales unsliced clip ranges so
  their sample duration stays fixed.
- Time signature is one numerator and denominator for the whole project.
- Time signature changes and markers are not implemented.

## Render mixdown

Open **FILE > Render Mixdown…** to render offline. The dialog sets:

- **File format**: WAV, AIFF, FLAC, MP3, or OGG Vorbis.
- **Bit depth**: 16-bit, 24-bit, or 32-bit where the format supports it.
- **Dither** and **Normalize**.
- **Export stems**, which writes one file per track in addition to the mix.
- **Range**, in beats. **Copy loop range** fills the range from the current loop.

The render runs offline through the same engine path as playback. Latency
compensation, device processing, and the master chain are included.

The default range spans the arrangement. If the end is not after the start, the
**Render…** button is disabled. The output path is chosen after starting the
render.

## Command line rendering

The application binary can render without opening the window:

```sh
cargo run -p notwig-app -- render path/to/project.notwig out.wav
cargo run -p notwig-app -- render path/to/project.notwig out.wav --start 8 --end 32
```

`--start` and `--end` are in beats. The CLI render writes a WAV file.

Other CLI commands:

```sh
cargo run -p notwig-app -- new path/to/project.notwig
cargo run -p notwig-app -- demo
cargo run -p notwig-app -- info path/to/project.notwig
```

## What is not implemented

Recording, count-in, punch in and out, tap tempo, markers, and follow-playhead
are not available. See the [Roadmap](../03_development/06_roadmap.md) for the
current status.
